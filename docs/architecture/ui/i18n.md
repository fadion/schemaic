# `ui/i18n.rs`

`i18n.rs` — **the interface's string catalogue**: Fluent, through `i18n-embed` (feature
`fluent-system`) and `i18n-embed-fl`, over the language `core::locale` chose. The catalogues
are `crates/schemaic-ui/i18n/<tag>/schemaic.ftl` — `en-GB` the source, and `de`, `sq`, `it`,
`nl`, `fr`, `es`, `ro` and `bg` each complete but machine-drafted and unreviewed, as its header
says — embedded in the binary by `rust-embed`, and `crates/schemaic-ui/i18n.toml` names
`en-GB` the fallback and the Fluent domain `schemaic`, after the app rather than the crate, so
that every crate drawing the interface can share the one catalogue. `schemaic-app` is the
second to read it: `LOADER` is `pub`, but `tr!` stays this crate's, because `fl!` checks a
message id against the *calling* crate's `i18n.toml` and a macro exported from here would carry
no check into the app — so the app has a `tr!` and an `i18n.toml` of its own, pointed at these
catalogues (the `schemaic-app` entry). One catalogue, one loader, checked from both crates.
**`tr!` is `fl!` against `LOADER`**, so a message
id and its argument names are checked against the `en-GB` file at compile time and a missing key
is a build error rather than a blank label — but *only* against `en-GB`, which is why the tests
below read the other files. The crate's `build.rs` prints `cargo:rerun-if-changed=i18n`,
because the non-test build otherwise records no dependency on the catalogues: an id renamed in
the `.ftl` alone left a stale build that still passed the check. `LOADER` is a `LazyLock<FluentLanguageLoader>` holding `en-GB` until
`init` says otherwise, and in every test, so English output never depends on the machine running
the suite (`the_global_loader_is_english_until_init`).
**`init(env, os, setting)` runs once, before any view is built**, and a second call is ignored
(a `OnceLock`): a label is built with its text and nothing re-renders when the setting moves, so
a language applied after the first view would leave that view English. The app reads all three
inputs — `SCHEMAIC_LOCALE`, `sys_locale::get_locales()` and the persisted key — and calls it in
`app_view` straight after `load_ui_state`, logging the answer, so this crate never touches the
environment. `active()` is the language on screen and
`would_draw(key)` what a *Language* setting of `key` would draw on this machine, from the `env`
and `os` `init` was handed rather than asking the OS again. `number_marks()` is the active
language's `NumberMarks`, and `figure`, `count`, `bytes` and `contrasting_bytes` write core's
English figures in them — the view's half of *Figures in the interface's marks*, with
`every_core_figure_a_view_shows_takes_the_interface_s_marks` the gate that keeps a view on it.
Units are the other half, and they are words rather than marks: `session_age`,
`staleness_age` and `poll_interval` word `activity::Age`, `stats::Span` and a poll interval
from `activity-age-*`, `props-age-*` and `activity-interval*` (German `4 min 02 s`, `3 Tg.`,
`Aus`), `session_age` padding the second figure to two digits as core does so a column of
ages lines up. Each has a private `_in(&FluentLanguageLoader, …)` sibling so
`ages_and_poll_intervals_read_in_the_interfaces_units` can ask German as well as hold the
English equal to core's `Display`. Run times are the same shape: `took` words `history::Took`
from `took-*` (`850 ms`, `12,3 s`, `2 min 05 s`) for a history row's outcome line and the
desktop notification, and `elapsed(ms)` is `took(transcript::elapsed(ms))` for the AI panel's
live counter — with `took_in` the sibling, and
`run_times_read_in_the_interfaces_units_and_marks` the test.
**`configure` loads a catalogue and *then* calls `set_use_isolating(false)`, and the order is
load-bearing**: a load swaps in fresh bundles and the flag is a setting of the bundles, so set
first it is silently undone. Fluent wraps every placeable in U+2068/U+2069 by default, so a
right-to-left value cannot reorder the sentence around it; with the marks on, every English
message that takes an argument differs from the literal it replaced by two invisible characters
— which the suite's English assertions would catch and a user would copy out of a message.
`a_message_with_an_argument_carries_no_isolation_marks` pins it, and was seen red with
`System (\u{2068}English\u{2069})` before the call. What it gives up is that protection, for
right-to-left data put into a message as much as for a right-to-left language; there is no
right-to-left interface, and one is not a goal (*The string catalogue*, under *UI conventions*).
`configure_from` does nothing else: the two pseudo-locales' transforms (`bundle.set_transform`
— `fluent-pseudo`'s accented text, and a `doubled` one that said each word twice) were deleted
with the locales and the `fluent-pseudo` dependency, their job of finding boxes too narrow for
longer text being done since by the real catalogues (*Layout for longer text*, under *UI
conventions*).
**Three catalogue tests stand in for what `fl!` cannot see.** At run time a malformed `.ftl` is
only logged and its broken messages fall back to English, unseen, so
`every_catalogue_parses_cleanly` parses every embedded file strictly with `fluent-syntax` (a
dev-dependency) and requires at least two of them; and
`no_translation_outlives_its_english_message` fails on an id a translation has and `en-GB` has
not — dead weight that reads as live, and usually a renamed id whose new name is untranslated;
and `a_translation_reads_only_the_variables_english_is_given` walks both ASTs, since `fl!`
checks a call's argument names against `en-GB` alone and a German `{ $nmae }` would draw a
placeholder unseen (seen red by renaming one). A message missing from a translation is not an
error: it falls back to English **message by message**, which is `load_languages` appending
`en-GB` behind the tag in `configure_from`, and `a_message_german_lacks_reads_in_english`
holds it over a fixture whose `de` has one message. A language with **no** catalogue folder is
not skipped: i18n-embed panics on it, so `every_language_s_catalogue_is_embedded` walks
`UiLanguage::ALL`, which core's `all_names_every_language_once` holds to every variant with
the `match` that makes a new one a compile error. Keeping an
incomplete catalogue out of users' hands is `SHIPPED`'s job.
**Three more read the translations language by language.**
`every_translation_reads_its_own_catalogue` asks each translation after German for
`settings-language`, since a catalogue that failed to load would answer English's *Language*
there and look like a fallback rather than a fault. `romanian_counts_in_its_three_plural_forms`
is the check that `ro` is the tag the bundle was built under: Fluent takes the CLDR plural
rules from the catalogue's tag, and only Romanian's reach `[few]` (2–19) and the *de* of
twenty or more (`20 de potriviri`). `each_translation_names_keys_by_its_keyboard_legends` pins
the `key-*` words to what the keyboard prints: Italian, French and Spanish keyboards carry their
own legends (*Maiusc*/*Invio*/*Canc*, *Maj*/*Entrée*/*Suppr*, *Mayús*/*Intro*/*Supr*, and
*Origine* and *Inicio* for Home), so those are translated, while Bulgarian, Romanian, Albanian
and Dutch keyboards print English's and only the space bar is named in the language — the test
covers Bulgarian of those four.
**`LanguageChoice` is the setting as Settings offers it** — `System` or `Fixed(UiLanguage)`,
`options()` being `System` then `SHIPPED`. `from_key` reads a key it does not offer (a newer
build's, a hand edit, an unshipped catalogue, a retired pseudo-locale's) as `System`, which is
also
what `resolve` makes of it (`the_language_setting_offers_only_what_ships`). With all nine
shipped, Settings lists `System` and then every language. `label()` names a
language by its endonym and the system entry as `System (English)` —
`settings-language-system` over the endonym the system would resolve to. `needs_restart()` is
`would_draw(key) != active()`, so choosing English on an English system changes the setting and
says nothing (`a_choice_that_draws_what_is_on_screen_needs_no_restart`, which — English being
on screen without `init` — holds `System` and English to no restart and every other shipped
language to one).
**Core's words are drawn here, not translated from core.** `object_kind(kind)` and
`object_kind_group(kind)` are `ObjectKind::label`'s *sequence* and `group_label`'s *Sequences*
in the interface's language (`kind-*`, `kind-group-*`): core's words stay English because the
CLI, the MCP server and the AI prompts read them, so the interface keeps its own beside them,
one exhaustive `match` per word. `english_names_every_object_kind_as_core_does` holds English
equal to core's for every `ObjectKind::ALL`, which is what keeps the converted sites
byte-identical in English and fails on a new kind with no message. Not every use of core's word
moves: the schema tree's `objgrp:`/`obj:` expansion keys (`object_group_key`, `object_key`) are
persisted and must not change with the language, and the tree's *AI explain* prompts are
English by rule — both keep `ObjectKind::label`/`group_label`. `environment_label` (`env-*`)
and `ai_data_label`/`ai_data_hint` (`ai-data-*`, `ai-data-*-hint`) are the same for
`connection::Environment` and `AiData`, here because more than one file calls them: the
connection form's pickers, the top bar's environment badge and Settings' data-access line.
`english_names_every_environment_and_data_level_as_core_does` holds them to core's.
